## 🚀 Quick Start

### Prerequisites
- Python 3.12+
- PostgreSQL 16+
- Redis 7+
- Bot Token from [@BotFather](https://t.me/BotFather)

### Local Development

```bash
# Clone and install
git clone <repo>
cd guardian-bot
pip install -r requirements.txt

# Configure environment
cp .env.example .env
# Edit .env with your credentials

# Run migrations
python scripts/migrate.py

# Start in polling mode (development)
BOT_TOKEN=your_token WEBHOOK_URL="" DATABASE_URL=... REDIS_URL=... python -m bot.main
```

### Docker Compose

```bash
cp .env.example .env
# Fill in BOT_TOKEN and BOT_OWNER_ID

docker-compose up -d
```

## ☁️ Deploy to Render.com

### Method 1: render.yaml (Recommended)

1. Push your code to GitHub
2. Connect the repo on [Render.com](https://render.com)
3. Render will auto-detect `render.yaml`
4. Set the required environment variables:
   - `BOT_TOKEN` — Your Telegram bot token
   - `BOT_OWNER_ID` — Your Telegram user ID

That's it! Render will provision PostgreSQL, Redis, and deploy the bot automatically.

### Method 2: Manual Setup

1. Create a **Web Service** on Render
   - Runtime: Docker
   - Health check path: `/health`
2. Create a **PostgreSQL** database
3. Create a **Redis** instance
4. Set environment variables from `.env.example`

### Required Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `BOT_TOKEN` | ✅ | From @BotFather |
| `DATABASE_URL` | ✅ | PostgreSQL connection string |
| `REDIS_URL` | ✅ | Redis connection string |
| `WEBHOOK_URL` | ✅ (prod) | Your app's public URL |
| `BOT_OWNER_ID` | ✅ | Your Telegram user ID |
| `WEBHOOK_SECRET` | Auto | Generated by Render |
| `SENTRY_DSN` | ❌ | Optional error tracking |

## 👑 ALEXA Owner Panel Additions

The bot keeps the original Guardian X feature set and adds an owner-only ALEXA panel:

- Owner-only `/owner` panel.
- `/owner` is removed from the default command menu and exposed to `OWNER_ID` only (when Telegram command scopes are available).
- Active Groups list.
- Per-group activity statistics and recent action logs.
- Per-group invite/public link retrieval.
- Add-to-group link for ALEXA.
- Confirmed Ban All flow per selected group.
- Silent individual ban attempts (no group spam messages).
- Existing tracked group members are used for Ban All; Telegram administrators/creators and the bot are skipped.
- `chat_member` updates are stored so newly observed/joining members can be tracked automatically.
- Configuration accepts `BOT_TOKEN`, `OWNER_ID` (or `BOT_OWNER_ID`), `API_ID`, and `API_HASH`.

Telegram does not provide bots with a general API to enumerate every existing member of a group. Therefore Ban All can only act on member IDs that ALEXA has legitimately tracked/received.

# ALEXA Telegram Bot - Deploy trigger


## PythonAnywhere quick start (ALEXA)
1. Install dependencies with `pip install -r requirements.txt`.
2. Copy `.env.example` to `.env` and set `BOT_TOKEN` and `OWNER_ID` (keep `.env` private).
3. Run from this project folder: `python3 -m bot.main`.
4. On PythonAnywhere, the bot uses the provided HTTP proxy for Telegram when available. If a configured PostgreSQL database cannot be reached, it falls back to a persistent local `alexa.db` SQLite database.

The owner panel is intended only for the configured `OWNER_ID`/`BOT_OWNER_ID`. A local SQLite fallback stores data on this host; it does not sync that data back to a remote PostgreSQL database.


## ALEXA legacy game commands

The Telegram command menu includes the owner-only `/owner` command in the configured owner's private chat only. Additional virtual coin-game commands are available:

- Economy aliases: `/bal`, `/wallet`, `/daily`, `/weekly`, `/monthly`, `/rank`, `/leaders`, `/toprich`, `/items`, `/task`.
- Virtual player game: reply to a member with `/kill` or `/rob`; `/protect 1d` buys protection (500 coins per started day by default); `/unprotect` disables it; `/revive` removes one virtual defeat (250 coins by default).
- Mini-games: `/card`, `/bomb`, `/bluff`, `/hack`, `/pfp`, `/topkill`, `/toprob`.
- Group management controls require Telegram administrator/creator status. The `/owner` panel is private-chat-only and checked against `OWNER_ID`/`BOT_OWNER_ID` on every action.

## Offline checks

Run `python scripts/smoke_check.py` for syntax/structure checks. These checks do not contact Telegram or prove that the bot token, proxy, database credentials, or Telegram permissions work. A live startup test is still required on the target host.

### Additional implemented controls

- `/rules` and `/setrules` store group rules; `/filter` and `/stopfilter` add/remove keyword replies; `/save`, `/get`, and `/clear` manage saved text; `/blocklist`, `/addblocklist`, and `/rmblocklist` manage blocked phrases.
- `/setflood`, `/flood`, `/setfloodmode`, and `/clearflood` configure in-memory flood protection. Anti-spam/flood counters reset when the process restarts.
- `/promote`, `/demote`, `/resetwarns`, `/warnings`, `/del`, `/pin`, and `/unpin` require group-admin status and bot permissions.
- Security toggles now cover duplicate spam, flood, suspicious promotions, links/invites, forwards, username heuristics, bot joins, raid/mass joins, and optional emergency lockdown. Heuristic filters can have false positives, so review the settings before enabling stricter modes.
- Default daily/weekly/monthly missions track message/game activity and award virtual coins/XP when claimed.
- `/disablecmd`, `/enablecmd`, and `/disabledcmds` let group admins disable specific commands while keeping recovery commands protected.

## PythonAnywhere free-account notes (ALEXA)

- Start the bot from the extracted project root so the local `.env` and `alexa.db` paths resolve consistently.
- Set `BOT_TOKEN` and `BOT_OWNER_ID` (or `OWNER_ID`) in `.env`. Keep the file private; never paste tokens into chat or commit them to Git.
- If `DATABASE_URL` is omitted, ALEXA uses the persistent local SQLite file `./alexa.db`. On PythonAnywhere free accounts, direct PostgreSQL connections to external hosts on port 5432 may be blocked; the SQLite fallback is local to this account and does not sync with Neon/PostgreSQL.
- ALEXA uses the host's `https_proxy`/`HTTPS_PROXY` environment variable for Telegram HTTPS requests when present.
- Install dependencies in a Python 3.12+ virtual environment with `pip install -r requirements.txt`, then run `python -m bot.main` from this directory. If startup logs say the bot is not active, check the required environment variables and the first error above that message.
- Free-account console processes may stop or collide on the optional health-server port. A health-server bind error is logged as a warning; it should not prevent polling from starting. Keep only one active bot process for the same token.

## Offline verification

Run `python scripts/smoke_check.py`, `python -m compileall -q bot scripts tests`, and (after installing requirements) `python -m unittest discover -s tests`. These checks validate source structure, syntax, the local SQLite schema, and content-lock regressions; they do not replace a live Telegram run with a valid bot token.
